# QAISAR OLYMP: usability and learning audit

Audit date: 2026-11-09. Scope: the existing GitHub Pages application, its learning data, browser persistence, Auth/REST client and supplied SQL policies. This record contains no pupil answers, essays or credentials.

## Preserved behavior

Existing diagnostic items, exercise banks, answer keys, fonts, themes, accounts, per-user storage keys, state version 1 and backend policy files are unchanged. Legacy JSON continues to import. Teacher feedback is separate from pupil state and imported manual marks never become trusted teacher grades. Tests use synthetic data. No user records were written to Supabase during this audit.

The baseline edit restriction is a learning-integrity improvement in the normal application workflow. This is a public self-study application with public answer keys and editable import files; it is not an invigilated, tamper-proof examination service.

## Validation

138 Node tests pass, including 19 added usability regressions. They cover actual event handlers in the modeled DOM, canonical vocabulary filters, post-key edit rejection, missing evidence, Writing bounds, topic priority, balanced sessions, Reading evidence, safe rendering, import cancellation/backup/queueing, failed assignment fetch recovery, visible stale feedback and teacher filtering. Existing mocked transport tests cover expiry, conflicts, account separation and unauthorized teacher actions. All JavaScript syntax and local asset references are checked.

The old manual-grade invalidation test now runs before answer-key release; a separate regression checks that the submitted baseline cannot be edited. Historical successful tests were not removed to conceal failures.

## Remaining limits and next priorities

1. **Hosted access control still needs verification in Supabase.** SQL defines RLS policies, but their deployment and actual two-pupil/teacher isolation were not tested here. Use the supplied `backend/verify-access.sql` plus real authorized accounts. Client-side role checks alone do not establish data security. Supabase's reference is <https://supabase.com/docs/guides/database/postgres/row-level-security>.
2. **Real browser/device QA is outstanding.** The supported browser facility is unavailable in this environment. Responsive CSS, focus rules and modeled DOM tests do not establish visual correctness or WCAG compliance. Inspect 320, 375, 768, 1024 and 1440 px, keyboard navigation, zoom, both themes and mobile form input.
3. **The current bank is finite.** Each topic has six lesson exercises and two three-question retests; two-form reuse is disclosed. Add more independent contexts before interpreting repeated success as transferable mastery. Forty vocabulary cards are a starting set.
4. **The three mocks reuse the six Reading texts.** Prior exposure is disclosed. Independent unseen texts are needed for a clean later measurement; the interface does not claim these are full official Olympiads.
5. **Listening and Speaking are not implemented.** They require appropriate audio, tasks, scoring and, for productive speaking, human assessment. Written-only progress does not measure those skills.
6. **Official alignment must be documented.** The actual event, stage, current official time limits and rubric need to be linked to the relevant source tasks. This audit did not revalidate the original two years of documents; it does not claim the new daily plan follows an official scoring blueprint.
7. **Writing still requires teacher feedback.** Word count, planning and checklists help revision but do not assess argument quality or language accuracy. Feedback is not automatically refreshed continuously; the account has a refresh action.
8. **Personal scheduling remains provisional.** The suggested session can support home study, but the competition date and sustainable weekly availability remain unknown. It is not a finalized calendar plan or a predicted score improvement.

## Suggested device acceptance route

Sign in as the pupil → open `Нәтижелерді көшіру` → export a backup → preview an appropriate JSON file → confirm → wait for `Серверде сақталды` → open the suggested session → study a priority topic → attempt new questions → review the mistake notebook → revise Writing → sign out → sign in as the linked teacher → refresh results → inspect priorities and exact essay feedback. Separately verify that a second pupil cannot access the first pupil's records.
